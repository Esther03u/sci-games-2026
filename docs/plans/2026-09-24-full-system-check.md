## 0. กติกาการตรวจ (อ่านก่อนลงมือ)

1. **มี DB เดียวคือ production** — dev ในเครื่องก็ชี้ Supabase ตัวจริง ไม่มี staging
   - ตรวจที่ *อ่านอย่างเดียว* ทำกับข้อมูลจริงได้เลย
   - ตรวจที่ *เขียนข้อมูล* (เริ่มแมตช์, กดคะแนน, จบแมตช์, สร้างข่าว) ให้ใช้ **แมตช์/ข่าว/PIN ชั่วคราว** ที่ขึ้นต้นชื่อด้วย `[TEST]` แล้วลบทิ้งท้ายรอบ (แบบเดียวกับ `smoke-test.mjs`)
   - ถ้าต้องลองกับแมตช์จริง (เช่น bracket progression) ให้จดค่าเดิมก่อน แล้วรีเซ็ตคืนทันที (เคยทำแล้ว 23 ก.ย. กับฟุตซอลหญิงคู่แรก)
2. **ห้าม `seed:matches --force`** ในรอบตรวจ
3. หน้า ISR (`/schedule`, `/results`, `/news`) แคช 30 วิ — แก้ข้อมูลแล้วยังไม่เห็น ให้รอ 30 วิก่อนสรุปว่าพัง
4. Browser pane ของ Claude ค้าง HMR — ผลแปลกให้เปิดแท็บใหม่ก่อน
5. ทุกข้อที่เจอ บันทึกลงตาราง §9 (ข้อ, หน้า, อาการ, วิธีทำซ้ำ, ความรุนแรง) — แก้ทีละเรื่อง ตามลำดับความรุนแรง

**ระดับความรุนแรง**
- **P0** — ใช้ในวันงานไม่ได้ / คะแนนผิด / คะแนนสดรั่ว / คนไม่มีสิทธิ์แก้ข้อมูลได้
- **P1** — ใช้ได้แต่สับสนหรือผิดบางกรณี
- **P2** — ความสวยงาม, ข้อความ

## 5. ระบบข้ามหน้า (cross-cutting)

### 5.1 สิทธิ์ — ตาราง anon / PIN / staff / admin × ทุกหน้าและทุก API
ยิงทุก API ใน `src/app/api/**` (16 route) ด้วย 4 บทบาท ตรวจว่าได้ 200/401/403 ตามที่ควร — ต่อยอดจาก smoke test ให้ครบทุก route:
`admin/[resource]` · `admin/bracket` · `admin/pins` · `admin/settings` · `admin/users` · `auth/me` · `check-status` · `live-summary` · `match/[id]` · `match/[id]/[action]` · `pin/login` · `pin/logout` · `register` · `score` · `score/undo` · `track`

### 5.2 คะแนนสดไม่รั่ว (P0 ถ้ารั่ว)
ระหว่างมีแมตช์ `[TEST]` สถานะ live: view-source `/results`, `/api/live-summary`, `/api/match/[id]`, และ query `matches` / `matches_public_v2` / `match_sets` / `score_events` ด้วย anon key → ต้องไม่เห็นเลข

### 5.3 Bracket progression ทุกกีฬา
จบคู่รอบแรก 1 คู่ต่อกีฬา (5 กีฬา) → ผู้ชนะเข้าชิงที่ 1, ผู้แพ้เข้าชิงที่ 3 ถูกช่อง → reopen แล้วรีเซ็ตคืน (จดค่าเดิมก่อน)

### 5.4 หลายเครื่องพร้อมกัน
2 เครื่องกดคะแนนแมตช์เดียวกัน + 5 กรรมการ 5 กีฬาพร้อมกัน + `/admin/live` เปิดค้าง → คะแนนตรงกันทุกจอ, ไม่มีแต้มหาย

### 5.5 โหลดและโควตา Free tier
จำลองผู้ชม 200–300 คนเปิด `/results` (poll 30 วิ) → ยืนยันว่า Supabase ถูกอ่านแค่ครั้งละรอบแคช; ดู egress ใน Supabase Usage ก่อน/หลัง

### 5.6 อุปกรณ์จริง
มือถือกรรมการ ≥2 รุ่น (Android + iPhone), จอสนาม (`/live` บนทีวี/โน้ตบุ๊ก), Wi-Fi สนาม + 4G
