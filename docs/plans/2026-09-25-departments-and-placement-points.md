# แผน: หน้าจับคู่สาขา–สี + ระบบคะแนนตามอันดับ (ที่ 1–4)

> เขียน 25 ก.ย. 2569 · สถานะ: **รอผู้ใช้ตัดสินใจ §4** (ยังไม่ลงมือ)
> คำขอ: (1) หน้าจับคู่สาขาและสีให้เห็นชัดว่าสาขาไหนอยู่สีอะไร (2) ระบบคะแนนรวมตามอันดับที่ 1/2/3/4 — ตอนนี้บอกแค่แพ้/ชนะ ไม่บอกคะแนน

---

## 1. สภาพปัจจุบัน

### 1.1 หน้าจับคู่สาขาและสี (`/admin/departments`)
- เป็นตาราง 2 คอลัมน์ "สาขาวิชา | ทีมสี" เรียงตามชื่อสาขา → ต้องไล่อ่านทีละแถวถึงจะรู้ว่าแต่ละสีมีสาขาอะไร
- บนมือถือตารางต้องปัดข้าง (แก้ให้ปัดได้แล้วเมื่อ 24 ก.ย.)
- ข้อมูลจริงตอนนี้ 8 สาขา สีละ 2:

| สี | สาขา |
|---|---|
| แดง | เทคโนโลยีดิจิทัล · วิทยาการคอมพิวเตอร์ |
| ฟ้า | เทคโนโลยีสารสนเทศ · นวัตกรรมอาหารและเครื่องดื่ม |
| เขียว | วิทยาศาสตร์สิ่งแวดล้อม · สาธารณสุขศาสตร์ |
| ม่วง | การจัดการภัยพิบัติและสิ่งแวดล้อม · คหกรรมศาสตร์ประยุกต์ |

- **ผู้ชมไม่เห็นข้อมูลนี้ที่ไหนเลย** บนเว็บ

### 1.2 คะแนนรวม (`team_standings`, migration 002)
- ทุกแมตช์ที่จบ: ชนะ 3 · เสมอ 1 · แพ้ 0 (`sports.win_points/draw_points/lose_points`) แล้วรวมทุกแมตช์ → เป็น **คะแนนแบบลีก** ไม่ใช่อันดับ
- ปัญหา: ทัวร์นาเมนต์นี้เป็นแพ้คัดออก 4 ทีม แต่ละรายการแต่ละสีเล่น 2 นัด → ที่ 1 ชนะ 2 นัด = 6 แต้ม · **ที่ 2 ชนะ 1 นัด = 3 แต้ม · ที่ 3 ชนะ 1 นัด (ชิงที่ 3) = 3 แต้ม** · ที่ 4 = 0 → ที่ 2 กับที่ 3 ได้เท่ากัน **ไม่สะท้อนอันดับ** และหน้าเว็บไม่เคยบอกว่าใครได้ที่เท่าไหร่ของแต่ละรายการ
- หน้าแรก (โพเดียม) และ `/admin` (ตารางอันดับ) ใช้ `total_points` จาก view นี้

### 1.3 รายการแข่งขันที่ให้อันดับ — **11 รายการ** (ทุกรายการ 4 สี มีรอบแรก 2 คู่ + ชิงที่ 3 + ชิงชนะเลิศ)
| กีฬา | รายการ |
|---|---|
| ฟุตซอล | ชาย · หญิง |
| วอลเลย์บอล | ชาย · หญิง |
| เซปักตะกร้อ | ชาย · หญิง |
| บาสเกตบอล | ชาย · หญิง |
| เปตอง | คู่ชาย · คู่หญิง · คู่ผสม |

อันดับของแต่ละรายการได้จาก 2 นัดสุดท้าย: **ชนะชิงชนะเลิศ = ที่ 1 · แพ้ = ที่ 2 · ชนะชิงที่ 3 = ที่ 3 · แพ้ = ที่ 4** (รวมกรณีชนะบาย `is_walkover`)

## 2. งานที่ 1 — หน้าจับคู่สาขาและสี

### 2.1 แอดมิน `/admin/departments`
- เปลี่ยนเป็น **การ์ด 4 ใบ ใบละสี** (สีพื้นตามทีม, ชื่อสี, จำนวนสาขา) และรายชื่อสาขาในสีนั้นเป็นชิป
- แต่ละชิปมีปุ่ม "ย้ายสี" (เลือกสีใหม่) และ "ลบ"; ปุ่ม "+ เพิ่มสาขา" ในแต่ละการ์ด (สีถูกเลือกให้แล้ว)
- สาขาที่ยังไม่มีสี (ถ้ามี) แสดงเป็นการ์ด "ยังไม่ได้จัดสี" ด้านบนสุด สีเตือน
- มือถือ: การ์ดเรียงลงมา 1 คอลัมน์, ไม่มีตารางปัดข้าง
- API เดิม (`/api/admin/departments` ผ่าน generic route) ใช้ต่อได้ ไม่ต้องแก้ DB

### 2.2 ผู้ชม (ถ้าเลือก — §4 ข้อ 4)
- ส่วน **"สาขาในแต่ละสี"** บนหน้าแรก (ใต้โพเดียม) หรือหน้า `/handbook` — การ์ด 4 สีแบบเดียวกันแต่อ่านอย่างเดียว
- ข้อมูล `departments` + `teams` อ่านได้โดย anon อยู่แล้ว (ไม่มีข้อมูลส่วนตัว)

## 3. งานที่ 2 — คะแนนรวมตามอันดับ

### 3.1 ฐานข้อมูล — migration ใหม่ (additive, idempotent)
- `app_settings.placement_points` = `[4, 3, 2, 1]` (ค่าเริ่มต้นตาม §4 ข้อ 1) → แอดมินแก้ได้ที่ `/admin/settings`
- view **`event_placements`**: 1 แถวต่อ (กีฬา, ประเภท, สี) พร้อม `place` 1–4 จากนัดชิงชนะเลิศ/ชิงที่ 3 ที่ **จบแล้ว** เท่านั้น (ยังไม่จบ = ยังไม่มีอันดับ) — ผู้ชนะคิดแบบเดียวกับ `team_standings` (เซต/แต้ม) ถ้าเสมอ = ไม่มีอันดับจนแอดมินแก้
- view **`team_placement_standings`**: ต่อสี — `total_points` (รวมคะแนนตามอันดับ), `golds`/`silvers`/`bronzes`/`fourths`, `events_done` (กี่รายการจบแล้ว จาก 11)
- เรียงอันดับรวม: คะแนนรวม → จำนวนที่ 1 → ที่ 2 → ที่ 3 (§4 ข้อ 3)
- GRANT SELECT ให้ anon (มีแต่ผลที่จบแล้ว ไม่มีคะแนนสด)
- `team_standings` เดิมเก็บไว้ (ไม่ลบ) แต่เว็บเลิกใช้

### 3.2 หน้าจอ
| ที่ | เปลี่ยนเป็น |
|---|---|
| หน้าแรก — โพเดียม | ใช้ `team_placement_standings.total_points` (ระบบนับถอยหลัง/เปิดเผยของเพื่อนใช้ต่อได้) |
| `/results` | เพิ่มส่วน **"ตารางคะแนนรวม"**: สี · 🥇 · 🥈 · 🥉 · ที่ 4 · คะแนน และ **"ผลรายการ"**: 11 การ์ด แต่ละใบบอก ที่ 1–4 ของรายการนั้น (+ คะแนนที่ได้) หรือ "ยังแข่งไม่จบ" |
| `/admin` — ตารางอันดับ | คอลัมน์เดียวกับข้างบน + "จบแล้ว x/11 รายการ" |
| `/admin/settings` | ช่องแก้คะแนนอันดับ 1–4 (มีตัวอย่าง "ถ้าตั้งแบบนี้ สีแดงจะได้…") |
| modal บันทึกผล (`/admin/matches`) | ข้อความ "ชนะ 3 เสมอ 1 แพ้ 0" → "นัดชิงให้อันดับ 1–4 ตามเกณฑ์คะแนน" |

### 3.3 เทสต์
- DB scenario: จบรอบชิง/ชิงที่ 3 ของ 1 รายการ → ได้ที่ 1–4 ถูกสี, คะแนนตาม `placement_points`, ชนะบายนับ, ยังไม่จบ = ไม่มีอันดับ, เปลี่ยนค่าคะแนนแล้วผลเปลี่ยนตาม, anon อ่านได้
- Vitest: ฟังก์ชันจัดอันดับรวม/tie-break, การ์ดผลรายการ
- ทดสอบบน production ด้วยแมตช์ `[TEST]` (ไม่แตะแมตช์จริง) แล้วลบ

### 3.4 ลำดับ deploy
ผู้ใช้รัน migration ใน SQL Editor → push → ตรวจ (view ใหม่ต้องมีก่อนโค้ดที่อ่านมัน)
