## 1. เป้าหมาย

1. **หาของเจอใน 10 วินาที** — ไฟล์เดียวทำเรื่องเดียว ไม่เกิน ~300 บรรทัด, โฟลเดอร์บอกหน้าที่
2. **มาตรฐานเดียว** — เขียนข้อมูล 1 ทาง (API), แสดง error 1 แบบ (Banner), format วัน/เวลา/ป้าย 1 ที่
3. **เร็วขึ้นโดยไม่ต้องคิด** — bundle หน้า public เล็กลง (ตัด ogl/ไอคอนที่ไม่ใช้, dynamic import ของหนัก), initial data ของ `/live` เล็กลง
4. **ปลอดภัยขึ้นเป็นผลพลอยได้** — เมื่อ admin เขียนผ่าน API ทั้งหมด ตัด policy `admin_write` บนตารางหลักได้
5. **พร้อมรับ dark theme** — แยก tokens/CSS ก่อน (ใช้ร่วมกับแผน dark theme)

## 2. ระดับที่เลือกได้

| | **A — จัดระเบียบในที่เดิม (แนะนำตอนนี้)** | **B — Feature-first ย้ายโฟลเดอร์** |

| ความเสี่ยงชนกับเพื่อน | ต่ำ–กลาง (แตะไฟล์เพื่อนน้อย เฉพาะ `MatchCard`/`MatchDetailModal` เรื่อง `getTeamStyle`) | **สูง** (rename ทุก import; เพื่อนที่มี branch ค้างจะ conflict ทั้งหมด) |

## 4. รายการงาน (เรียงตามลำดับทำ)

### P1 — Quick wins (≈ 0.5 วัน, ความเสี่ยงต่ำ, ไม่แตะไฟล์เพื่อน)
1. **tooling**: `.gitattributes` (`* text=auto eol=lf`) + renormalize 1 commit, `.editorconfig`, `.prettierrc` (+ `npm run format`, printWidth 110 ให้ใกล้สไตล์ปัจจุบัน), แก้ ESLint error เดิม 8 จุด
2. **ลบโค้ดตาย**: `AthletesClientView.js`, `BackgroundWaves.jsx`, `useToast.js` (+`Toast.js` ถ้าไม่ใช้), หน้า `/athletes` `/standings` (ตัดสินใจ: ลบ หรือทำจริง — เสนอ **ลบ** และเอาออกจาก README)
3. **`lib/format.js` + `lib/labels.js`**: รวม `fmt*`, `relativeTime`, `fmtRemaining`, `EVENT_DAYS` (แทน `'2026-10-09'` 7 ไฟล์), `ROUND_LABEL`, `EVENT_LABEL`, `ACTION_LABEL`; `constants/index.js` → ลบข้อมูลเก่าที่ไม่ตรง DB, เหลือเฉพาะที่ใช้ แล้วย้ายเข้า `labels.js`
4. **`components/ui/Banner.js`** (`kind: error|warn|info|success`) + **`ConfirmDialog.js`** (บน Modal) → แทน banner JSX ซ้ำ 6 ที่ และ `alert()`/`window.confirm()` 8+4 ไฟล์
5. **`components/ui/AdminTable.js`** (th/td/empty row) ใช้ใน `AuditLog`, `PinManager`, `DataTable` เดิม
6. **`lib/api/client.js`** `apiRequest()` = `adminApi` + `NetworkError` จาก `ScoreInput` → ใช้ทั้ง staff/admin
7. **`scripts/lib/env.mjs`** ใช้ใน 3 scripts + เพิ่ม `scripts/seed-matches.mjs` (อ่าน `data/handbook.js` → insert `matches` จริง; จำเป็นสำหรับ Phase 5 อยู่แล้ว)

### P2 — โครงสร้าง (≈ 1.5–2 วัน)
8. **แตก `ScoreInput.js`** → `staff/ScoreInput/{index,MatchPicker,ScorePad,ConfirmFinish}.js` + `hooks/useScoreQueue.js` (optimistic queue + retry + pending) + `hooks/useMatchSync.js` (realtime merge + wake lock) — เขียน unit test ให้ `useScoreQueue` (reducer ล้วน)
9. **แยก `globals.css`** เป็น `src/styles/*.css` ตามข้อ 3 (ลำดับ import เดิมเพื่อไม่เปลี่ยน cascade); ขั้นนี้ทำพร้อม token ของ dark theme
10. **`lib/queries/`**: `live.js` (ย้าย `loadLiveData`), `staff.js` (`loadScoringPage`), `admin.js` (`loadAudit`, `loadBracket`…) + helper `withPageData(fn, fallback)` ตัด try/catch ซ้ำใน 21 pages → page เหลือ ~15 บรรทัด
11. ✅ (21 ก.ย. — ทำเป็น route เดียว `/api/admin/[resource]` + whitelist `lib/api/adminResources.js`; migration เป็น **005**) **ทางเขียนข้อมูลเดียว**: เพิ่ม routes `/api/admin/{matches,news,athletes,departments,schedules}` (CRUD + `createAuditLog`) แล้วเปลี่ยน 5 manager เก่าให้เรียกผ่าน `apiRequest`; `MatchEditor` แก้คะแนน → `/api/match/[id]/override` (ได้ `score_event`); จากนั้น **migration 004** ลบ policy `admin_write` บน `matches, announcements, athletes, registrations, departments, sport_schedules` (client เหลืออ่านอย่างเดียว)
12. **`lib/team-style.js`** รวม `getTeamStyle()` จาก `MatchCard`+`MatchDetailModal` (แตะไฟล์เพื่อน 2 ไฟล์ — ทำเป็น commit เดี่ยว นัดเพื่อน)
13. **`/results` vs `/live`**: `results/page.js` (689 บรรทัด, client-only fetch ทั้งตาราง) ซ้ำหน้าที่กับ `/live` + `/live/[sport]` → เสนอให้ `/results` ใช้ `useLiveScores` + component จาก `live/` แล้วเหลือแค่ตัวกรอง (ลดได้ ~400 บรรทัด) — **ต้องคุยกับเพื่อน** เพราะเป็นหน้าที่เพื่อนทำล่าสุด
14. **`data/handbook.js`**: ย้าย `tournamentData.js`, และหลัง seed แมตช์จริงแล้ว **ตัด fallback** ออกจาก `/`, `/schedule`, `/results`, `ScheduleGrid` (เหลือ empty state) — ลดโค้ดและกันข้อมูลปนกันอีก

### P3 — Performance & คุณภาพ (≈ 0.5–1 วัน)
15. **ไอคอน**: ลบ `animate-ui/icons/*.jsx` ที่ไม่ถูก import (20 ไฟล์/2,460 บรรทัด → เหลือ `index.js` + `icon.jsx` ถ้าจำเป็น); วัดด้วย `next build` ก่อน/หลัง
16. **Dynamic import ของหนัก**: `GradientWaves`(ogl) → `next/dynamic({ ssr:false })` หรือแทนด้วย CSS gradient ถ้าเพื่อนโอเค; `AnalyticsCharts`(chart.js), `PdfGenerator`(jspdf+jszip) → dynamic เฉพาะหน้า admin นั้น
17. **`/live` payload**: `loadLiveData` ดึง `score_events` 300 แถวทุกครั้ง → ดึงเฉพาะแมตช์ที่ live/วันนี้ (ผู้ชมไม่ใช้ `lastEvents`) และให้ `useLiveScores({ withEvents })` เลือกได้; `matches` เรียงแล้วส่ง `select` เฉพาะคอลัมน์ที่ใช้
18. **`force-dynamic` ทุกหน้า**: หน้า `/news`, `/schedule` เปลี่ยนเป็น `revalidate = 30` ได้ (ลดโหลด Supabase ตอนคนเข้าเยอะ) — `/live` คงเดิม
19. **Tests**: Vitest ให้ `format.js`, `labels.js`, `matchesForSport`/`sportData` grouping, `useScoreQueue`; `npm run test:db` เพิ่ม scenario migration 004; smoke เพิ่ม admin CRUD routes
20. **JSDoc types** ใน `lib/types.js` (`@typedef Match/Sport/Team/ScoreEvent`) ให้ editor ช่วย — ไม่ย้ายเป็น TypeScript ตอนนี้ (ต้นทุน ~3 วัน กับไฟล์ 130 ไฟล์ ไม่คุ้มก่อนงาน; ใส่ในข้อเสนอหลังงาน)
